# 1. Кластер: кто за что отвечает

## Какую проблему решает Kubernetes

Запустить контейнер один раз недостаточно. Нужно выбирать место запуска, восстанавливать потерянные экземпляры, поддерживать их количество и обновлять приложение.

Kubernetes принимает описание желаемого состояния и постоянно работает над его поддержанием. Например, `replicas: 3` означает «нужно три Pod», а не «один раз создай три Pod».

## Механизм

| Компонент | Ответственность |
|---|---|
| API Server | Точка входа в Kubernetes API: принимает запросы клиентов и компонентов |
| etcd | Хранилище данных о состоянии кластера |
| Controller Manager | Запускает контроллеры согласования состояния |
| Scheduler | Выбирает Node для Pod, которому ещё не назначен узел |
| kubelet | Агент на Node: обеспечивает запуск и контролирует контейнеры Pod |

Первые четыре компонента относятся к Control Plane. Kubelet работает на узлах, в том числе на узле Control Plane, если там запускаются Pod.

```text
kubectl → API Server → сохранённая конфигурация
                            ↓
                 контроллеры создают нужные объекты
                            ↓
                 Scheduler выбирает Node для Pod
                            ↓
                 kubelet обеспечивает запуск контейнеров
```

Это схема ответственности, а не буквальная последовательность прямых вызовов между всеми компонентами.

## Понятия, которые нужно различать

| Понятие | Смысл |
|---|---|
| Kubernetes | Система оркестрации контейнеров |
| Minikube | Инструмент создания локального Kubernetes-кластера |
| `kubectl` | Клиент Kubernetes API |
| Node | Узел кластера, на котором могут выполняться Pod |
| Pod | Единица запуска одного или нескольких связанных контейнеров |
| kubeconfig | Настройки подключения: кластеры, пользователи, contexts |
| Context | Выбранная комбинация cluster + user + namespace |
| Namespace | Логическая область для ресурсов внутри кластера |

Namespace не создаёт отдельный кластер и сам по себе не гарантирует сетевую изоляцию. Node — ресурс уровня кластера, а Pod принадлежит namespace.

**Label** — метка объекта, например `app=web`. **Selector** — условие выбора объектов по меткам. Это способ группировки и поиска, а не имя или владелец объекта.

## Основные команды

```bash
# Проверить, с каким окружением работаешь
kubectl config current-context
kubectl config get-contexts
kubectl config use-context NAME

# Посмотреть узлы и Pod
kubectl get nodes
kubectl get pods -n study
kubectl get pods -A

# Увидеть IP, узел и метки Pod приложения
kubectl get pods -n study -l app=web -o wide --show-labels

# Исследовать конкретный объект
kubectl describe pod POD -n study
```

`-n` задаёт namespace, `-A` показывает все namespace, `-l` фильтрует по labels. `get` даёт обзор, `-o wide` добавляет поля, `describe` раскрывает подробности и события.

## Типичные ошибки понимания

- `kubectl` не запускает контейнеры самостоятельно: он обращается к API.
- `Ready` у Node означает готовность узла, а не исправность всех приложений на нём.
- `kubectl get all` показывает распространённые типы ресурсов, но не все: например, Secret и ConfigMap в этот набор не входят.
